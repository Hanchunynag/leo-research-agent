# RRF Top-20 与 BGE Cross-Encoder 精排分析

本实验冻结 21 道问题、135 个 Chunk v2.1、BM25 Top-20、BGE-M3 Dense
Top-20、RRF `k=60` 和 RRF Top-20。精排模型为固定 revision 的
`BAAI/bge-reranker-v2-m3`，使用 1024 token、batch size 4、CPU 和原始 logits。

## 候选池上限

BM25 Top-20 与 Dense Top-20 并集的平均 Oracle Recall 为 0.928571，任一相关
证据命中率为 0.952381；平均并集候选数为 29.619。RRF 截断到 Top-20 后仍保持
相同 Oracle Recall，因此本轮 RRF 截断没有丢失额外相关证据。

Q011 完全不在联合候选池；Q013 的两个相关 Chunk 只召回一个。因此 Reranker
无法补回 Q011，也无法让 Q013 达到完整 Recall。

## 排名质量

| 指标 | RRF | Reranker | 变化 |
|---|---:|---:|---:|
| Recall@1 | 0.380952 | 0.571429 | +0.190477 |
| Recall@5 | 0.809524 | 0.785714 | -0.023810 |
| Recall@10 | 0.880952 | 0.928571 | +0.047619 |
| MRR | 0.540873 | 0.710979 | +0.170106 |
| nDCG@10 | 0.623224 | 0.741598 | +0.118374 |

Reranker 把 RRF Top-20 中所有可用 qrel 都排进 Top-10，达到候选池 Oracle
Recall。它显著改善首位准确率、MRR 和 nDCG，但 Recall@5 有轻微退化，说明
Cross-Encoder 不是单调改进器，仍必须保留问题级诊断。

## 问题级升降排名

改善 7 题：Q004 由 12→3，Q007 由 2→1，Q008 由 4→1，Q010 由 3→2，
Q013 由 3→1，Q019 和 Q020 均由 5→1。Q004 说明精排可以救回被双路 RRF
候选压低的 Dense 单路强证据；Q008、Q019、Q020 则说明 Cross-Encoder 对局部
问题—证据关系的判断明显强于单向量相似度。

持平 9 题：Q001、Q002、Q003、Q005、Q009、Q014、Q015、Q018、Q021。

退化 4 题：

- Q006 由 4→9，但精排第 1 名摘要 Chunk 实际完整列出 pseudorange、Doppler、
  以及二者融合三种场景；冻结 qrel 只标注结论 Chunk。这主要是 qrel 覆盖不足，
  应进入人工裁决队列，不能据此静默修改本轮基线。
- Q012 由 3→8，属于真实退化。模型将另一篇论文中语义非常接近的卫星位置/速度
  协方差和参考系旋转段排在前面，说明跨论文近重复方法描述仍会误导 Cross-Encoder。
- Q016 由 8→9。该题此前已经发现概述 Chunk 与完整状态向量 Chunk 的标注边界，
  变化很小且相关证据仍在 Top-10。
- Q017 由 3→4。答案是局部的陀螺仪角速度与加速度计比力事实，模型仍受到同论文
  摘要和整体框架段影响，但没有跌出 Top-5。

Recall@5 的净下降来自 Q006、Q012 各损失一次命中，Q004 新增一次命中，Q020
由半召回变为全召回，最终净变化为 -0.5/21。

## CPU 性能

模型加载单独 warmup：Dense 3778.520 ms，Reranker 885.324 ms。稳定态结果：

| 阶段 | Mean | P50 | P95 |
|---|---:|---:|---:|
| 候选召回 | 136.741 ms | 121.886 ms | 239.461 ms |
| 20 对 Cross-Encoder 精排 | 14010.145 ms | 14225.825 ms | 17181.199 ms |
| 端到端 | 14146.983 ms | 14346.666 ms | 17299.847 ms |

420 个 Query–Chunk 对的总体吞吐量为 1.428 pair/s，端到端吞吐量为 0.071
query/s。质量基线成立，但当前 CPU 配置不适合交互式在线查询。后续性能实验应将
GPU、候选数、max length、量化或更小模型作为独立变量，不能覆盖本基线。

结论：Reranker 在冻结候选池上显著改善整体排序，并达到 Top-10 Oracle 上限；
下一阶段可以进入 LLM 上下文组装、证据引用与拒答机制，但仍不应先做 Agent 或
复杂 Query Rewrite。
